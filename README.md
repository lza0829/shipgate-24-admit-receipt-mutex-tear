# 发版闸（Shipgate）

骨架：发版申请入闸 → 环境晋升裁决 → 放行/回滚窗 → 发布结果对账

- 前端 http://127.0.0.1:6800
- API http://127.0.0.1:11800
- 数据库环境变量 `SHIPGATE_DB`（容器内默认 `/data/shipgate.db`）

```bash
docker compose up -d --build
```

## 同应用入闸互斥（臂一：同应用只许一单活跃在途）

后到的整笔入闸失败，不占在途、不挂流水线、总览不计双在途。互斥结果由两侧入闸写口、发版单、应用、流水线挂接、总览、审计共同对齐，不靠前端提示兜底。

- **应用占用位 `app_locks`**：每个应用至多一行，`release_id UNIQUE`，是在途的唯一事实源。入闸先取位再写在途态，同成败；回滚/关闭终态释放。
- **单写者事务 `write_tx()`**：入闸/晋升/回滚/关闭/排队均走 `BEGIN IMMEDIATE`，事务内按写时规则重放占用位，消除并发双入闸的 TOCTOU；WAL + `busy_timeout` 让并发写口排队。
- **在途态枚举**：`已入闸 / 晋升中 / 已放行 / 回滚中`，与占用位逐行对齐；**排队态** `排队中` + `queued_at` 字段可见可核，不占在途、不可晋升。
- **排队与唤醒**：待入闸单在同应用已有占用时可入排队；占用单回滚/关闭后由终态写口把排队单唤醒回「待入闸」（不自动入闸、不装成已入闸）。
- **失败回执与状态同刷**：互斥拒绝返回 409 结构化回执（原因、占用单号、占用位），同事务写「互斥/入闸互斥拒绝」审计；失败单撤回到入闸前，无 `current_env`、无入闸时间、无占用。
- **排队单误晋升**：晋升写口与入闸写口对排队态硬阻断（409）；晋升还要求本单持有占用位。
- **半截双挂收口**：`reconcile_app_lock()` 按写时规则重放，同应用多笔在途时最早入闸者持位、其余收口为「已关闭」并留「互斥/占用收口」审计；`POST /api/应用/{id}/互斥重放` 可主动触发，对账页逐应用给出占用位明细与违例。

### 写口与读口

| 面 | 对齐方式 |
| --- | --- |
| 入闸 `POST /api/发版单/{id}/入闸` | 单写者事务取占用位，冲突 409 + 互斥审计 |
| 排队 `POST /api/发版单/{id}/排队`、关闭 `POST /api/发版单/{id}/关闭` | 排队可见可核；关闭释放占用并唤醒排队 |
| 晋升 `POST /api/发版单/{id}/晋升` | 排队硬阻断；须持有占用位，半截双挂在此收口 |
| 回滚 `POST /api/发版单/{id}/回滚` | 终态释放占用位并唤醒排队 |
| 发版单详情/列表 | 带 `占用应用`、`排队时间` |
| 应用名册 `GET /api/应用` | 带占用发版单、占用起始、排队单数 |
| 总览 `GET /api/总览` | 在途格以占用位为准；排队单列，不计在途 |
| 对账 `GET /api/对账` | 逐应用在途态/占用位重放、互斥违例应用 |
| 审计 `GET /api/审计` | `kind=互斥`：入闸互斥拒绝、入排队、排队唤醒、占用收口 |

互斥只管同应用；跨环境（跨环）晋升规则另立。
